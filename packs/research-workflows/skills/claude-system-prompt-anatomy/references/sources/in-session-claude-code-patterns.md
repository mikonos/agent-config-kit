# 一手样本 · 本会话 Claude Code 系统提示词的可观察模式

> **来源等级:一手（直接观察）。** 主 agent 此刻正运行在一份真实的 Claude Code 系统提示词之下，本文件抽取其**设计模式与结构**，已抽象、未逐字转录专有全文与内部安全条款。
> 抽取日期:20260629。

## 0. 最重要的发现:三层分层（provenance layering）

真实运行时的提示词不是一整块，而是**按来源分层、且每层信任级别不同**:

| 层 | 作者 | 内容 | 指令权 |
|---|---|---|---|
| Harness 层 | Anthropic | 运行时机制（输出渲染、权限模式、工具、并行调用、上下文管理） | 系统级 |
| 项目协议层 | 用户（CLAUDE.md） | 项目身份、规则、验收 | 覆盖默认行为（显式声明 "OVERRIDE any default behavior"） |
| 动态上下文层 | harness 注入 | `<system-reminder>`、hook 输出、召回的记忆 | **明确降级**:背景信息，非用户指令 |

这正是 prompt-design 里"外部内容只有信息权"的**真实成品形态**:每段注入内容都带 provenance 标签，并显式说明它是不是指令。

## 1. 身份:一句话，不膨胀

开篇用一句定义"是什么 + 角色 + 运行环境（SDK）"，随即转入能力与边界。**没有**世界观长篇。对照 prompt-design「身份膨胀」反模式——官方成品恰恰极克制。

## 2. Harness 段:把"运行时事实"与"你是谁"分开

单设一段讲机制，与身份/项目规则隔离。包含:输出按 GFM 在终端渲染、权限模式由用户选、被拒的调用不要原样重试、`<system-reminder>` 由 harness 注入非用户、hook 输出当作用户反馈、优先用专用工具而非 shell、独立调用并行。

## 3. 对照式祈使「do X, not Y」

高频句式:给正向指令的同时绑定负向边界。例:"用专用文件/搜索工具，而不是 shell 命令"；工具描述里"避免用 cat/head/tail/sed/awk"。每条规则自带反例，可测、不含糊。

## 4. 行动—风险闸（permission in practice）

"难以撤销或对外的动作，先确认——除非已被持久授权或明确放行；一处的批准不延伸到下一处。"这是 prompt-design 三层权限（Regular/Explicit/Prohibited）的口语化成品:用"可逆性 + 对外性"判定是否需要确认。

## 5. 反过度追问 / 反过度工程

明示:"当你有足够信息去做时，就做。"——不要重复推导已确立的事实、不要重新litigate已定的决策、给建议而非穷举式综述。把"别问废话、别镀金"写成行为，不靠模型自觉。

## 6. 忠实汇报 / 反吹牛（anti-sycophancy 的运营版）

"测试失败就说失败并附输出；跳过的步骤就说跳过；做完并验证了就平实陈述、不加 hedging。"反谄媚在这里不是"别拍马屁"，而是**对结果的诚实义务**。

## 7. 验证工作流写成显式状态机

`<preview_tools>` 把"改完怎么验证"写成编号步骤，并铁律:"绝不让用户手动检查——自己验证并直接给出证据（截图/日志/网络请求）。"对照 prompt-design「输出与验证」——成品把验证做成了流程，不是一句愿望。

## 8. 输出适配渲染载体

显式假设"输出在终端按 GFM 渲染"；文件引用要写成可点击的 markdown 链接（含 `:line`）；PR/issue 用全 URL。输出风格服务于载体。

## 9. 大规模工具的延迟加载（ToolSearch / deferred tools）

工具先以**名字**暴露、schema 按需加载（"calling them directly will fail；先用 ToolSearch 加载"）。这是工具数量爆炸时的扩展模式:命名空间可见、细节延迟。

## 10. Skill 作为按需能力 + 阻塞式措辞

Skill 经 Skill tool 调用;用"BLOCKING REQUIREMENT""MUST"等强措辞标注不可跳过的动作。优先级靠大写与"IMPORTANT/OVERRIDE"分级，而非排版。

## 11. 记忆协议:结构化文件 + 索引 + provenance 警告

文件式记忆，带 frontmatter;一个索引文件每会话载入;并警告"召回的记忆反映写入时的状态——若提到某文件/函数/flag，推荐前先核实仍存在"。记忆带**时效与可信度免责**，不当作即时真相。
