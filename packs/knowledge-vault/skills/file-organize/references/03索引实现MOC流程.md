# 用 03_索引 实现 MOC 的流程

> 物理按天存放（05）+ MOC 用链接拉取（03）。本文件在 **file-organize 内闭环**：从「笔记落 05」到「在 03 的 MOC 里被链接」、写 `indexed: true` 与 `memory/入网` 日志。链接写入、索引更新、入网标记属于非破坏性维护，不需要用户逐次确认。

---

## 索引层级与命名约定（必守）

索引文档的**命名与存放**按「顶级 → 领域」分层，不按原文/单篇标题。

| 层级 | 命名规则 | 存放位置 | 示例 |
|------|----------|----------|------|
| **顶级索引（Hub）** | `索引_<主题>.md`，一个主题一个 Hub | `03_索引/` **根目录** | `索引_OpenClaw.md` |
| **子专题索引** | `索引_<主题>_<领域>.md`，按**领域**命名，不按原文/文章名 | `03_索引/<主题>/` **子目录** | `索引_OpenClaw_多Agent与一人公司.md`、`索引_OpenClaw_人格与配置.md` 存于 `03_索引/OpenClaw/` |

**要点**：
- 子专题索引名 = **领域**（如「多Agent与一人公司」「人格与配置」），不是某篇文章标题（如「一人公司实操」「与AI助手人格化」）。
- **结构笔记可以按原文**：结构笔记/文献笔记/摘录允许用原文标题命名（便于复现阅读顺序），但这类「原文名」**不得**进入索引文件名。
- **索引严格按领域**：索引文件名中**不得**出现作者/来源（如「笔记侠」）、日期/批次（如「20260216」）、活动名（如「2026春节」）、单篇文章标题；这些信息只写在索引正文的「来源说明」或 frontmatter（如 `source:`）。
- 非顶级索引一律放在对应主题的**子目录**下，不与顶级索引平级堆在 03 根目录。
- 入网时「树干→树枝」：优先挂在最贴切的**子专题索引**，再视需要挂顶级索引。

---

## 模型（你们现在的约定）

| 层级 | 位置 | 作用 |
|------|------|------|
| **物理存放** | `05_每日记录/YYYY/MM/YYYYMMDD/` | 笔记文件按天落在这里，由本 skill 决定 |
| **MOC（入口）** | `03_索引/`（顶级在根目录，子专题在 `<主题>/` 下） | 索引笔记 = MOC，用 `[[链接]]` 指向 05 里的笔记；笔记**不必挪动**，仍在 05 |

检索路径：**从主题找** → 打开 03 里某个索引（MOC）→ 点链接 → 跳到 05 里某天的某笔记。

---

## 缺的一环：入网

- **有物理位置**：笔记已在 05/某天。
- **要补的**：让这篇笔记在 **至少一个 03 的索引（MOC）里出现**，否则只能靠「记得在哪天」或全文搜索找到它。

**入网** = 在 03_索引 的某个（或多个）索引里，为该笔记添加入口（关键词 → `[[20260408_reference_ClaudeCode换号查渠道切换笔记]]`），在笔记底部加反链回索引，校验通过后写 `indexed: true`。

## 流程：笔记落 05 后 → 入网到 03（本 skill 内闭环）

```
笔记已落 05（归位完成）
    ↓
执行下方「入网步骤」
    ↓
该笔记在 03 的 MOC 里可被找到
```

## 入网步骤（本 skill 内执行）

### Step 0：读文件与判定边界

先读取目标笔记、候选索引和 `03_索引/00_索引_关键词总表.md`。若归属明显不确定，写入「待判断」清单，不强行标 `indexed: true`。

### Step 1：提取关键词

阅读该笔记内容，按 **What / How / Why** 提取 3–5 个核心关键词。问：这篇笔记的核心概念是什么？未来我会用什么词来找它？

### Step 2：索引候选发现（含「树干→树枝」优先）

- 遍历 `03_索引/` 下所有索引文件（含子目录中的索引），读取其「关键词」区域。
- 对每个关键词，判断与哪些索引**语义相关**（直接匹配、概念从属、应用场景、跨域关联）。
- **层级优先（树干→树枝）**：当同一主题下既有「顶级索引」又有「其下子目录/子索引」时，**优先选择最贴切的最细粒度索引（树枝）**添加入口；仅当没有合适分支、或该笔记是跨分支总览时，才挂在顶级索引（树干）。目标：避免大量笔记堆在树干导致顶级索引过载、难维护。
- 得到候选索引列表（可多个）。同一笔记可入多个索引（多入口可达），但优先写入分支索引。

### Step 3：在索引中添加入口

对每个选中的索引：

- **若该关键词尚未出现在该索引中**：在合适位置（或「关键词」区）添加一行：  
  `**[关键词]** → [[本笔记文件名]] — [一句话核心价值]`
- **若该关键词已存在**：若本笔记能独立回答该词（不同视角），则追加：  
  `**[关键词]** → [[原笔记]], [[本笔记]] (补充视角)`  
  否则只在本笔记与原有笔记间建双向链接，不改索引。

### Step 4：在笔记底部加反链

在本笔记文末添加一行（或「相关索引」小节）：  
`相关索引：[[索引A]] · [[索引B]]`  
确保每个本次添加入口的索引都出现在这里。

### Step 5：写入入网标记与日志

校验通过后：
- 在目标笔记 YAML frontmatter 写入 `indexed: true`
- 在 `memory/入网/YYYYMMDD.md` 记录：笔记路径、归属索引、一句判定依据

### 验收

- 该笔记至少在 **1 个** 03 的索引里出现（≥1 条入口）。
- 该笔记底部有反链回这些索引。
- **树干→树枝**：若有合适子索引，已优先挂在分支而非仅挂在顶级索引。
- 整体满足 **≥2 条双向可达路径**（可与 file-organize 输出里的连接建议合并）。
- YAML 已有 `indexed: true`，并已写入 `memory/入网/YYYYMMDD.md` 处理日志。

## 归位与入网配套（强制）

**归位到 05 的笔记，须在同一轮内完成入网**：在至少 1 个 03 索引中添加入口，并在该笔记底部加反链。不得只做归位、不做入网；清晰归属不需要等用户确认。

| 场景 | 要求 |
|------|------|
| 刚写完/刚移动一篇笔记到 05 | **必须**在归位后同一轮对话内按本流程执行入网 |
| 批量移动/整理到 05 | 每篇被归位的笔记均需执行入网步骤，可批量但不可省略 |
| 深度阅读/项目收尾 | 该流程要求的「索引入网」即按本文入网步骤执行 |
| 积压了一批 05 里的笔记未入网 | 对 05 下某目录或日期范围的笔记，逐篇按本流程入网 |

---

## 本 skill 的完整闭环

| 阶段 | 本 skill 所做 |
|------|----------------|
| **归位** | 决定笔记物理路径（默认 05/YYYY/MM/YYYYMMDD），输出路径与 ≥2 条连接建议；必要时执行移动。 |
| **入网** | 按本文「入网步骤」在 03_索引 中添加入口、在笔记底部加反链、写 `indexed: true` 和入网日志，使该笔记从 MOC 可被找到。 |

单篇、归属清晰的场景可在 file-organize 内完成「物理存放 + 用 03 实现 MOC」。深度连接、批量归网、近期未入网扫描等场景，按 `link-proposer` / `index-note` / `daily-network` 的规则扩展执行；这些常规图谱写入仍不需要用户逐次确认。
