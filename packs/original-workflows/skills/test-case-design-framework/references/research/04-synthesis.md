# 综合蒸馏

## 三人分工

- **Cem Kaner**：决定先测什么最值钱
- **Glenford Myers**：决定基础用例该怎么设计才不幼稚
- **Boris Beizer**：决定怎样避免覆盖结构性盲区

## 统一框架

测试用例设计不是只做一件事，而是三层叠加：

1. **价值层**
   - 这个用例在帮谁降低什么风险？
   - 这是 Kaner 层。

2. **方法层**
   - 我是否至少用过等价类、边界值、错误猜测等基本武器？
   - 这是 Myers 层。

3. **结构层**
   - 我是否遗漏了关键状态、关键组合、关键路径、关键可测性前提？
   - 这是 Beizer 层。

## 最终结论

- 没有 Kaner，用例容易整齐但没杀伤力。
- 没有 Myers，用例容易混乱、靠直觉、难复用。
- 没有 Beizer，用例容易局部聪明、整体漏洞。

最强的测试用例设计，不是三选一，而是：
**Kaner 决定优先级，Myers 决定基本手法，Beizer 决定覆盖完整性。**
