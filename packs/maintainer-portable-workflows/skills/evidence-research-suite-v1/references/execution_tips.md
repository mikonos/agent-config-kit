# 执行经验与技巧

> 基于 product AI-Native 家庭日历机的首次完整执行总结

## 执行策略

### 1. 知识库先行
在执行任何工具之前，**先穷尽已有的知识库**：
- 用户评论数据（JTBD分析结果）
- 竞品分析
- 战略会议纪要
- 市场细分数据
- 产品定义文档

已有数据的质量直接决定产出的"接地气"程度。没有数据的工具输出容易变成"正确但空泛"的模板。

### 2. 工具间的链式依赖
工具不是并行的，而是**严格串联**的：

```
Tool4 (分群) → Tool7 (功能需求) → Tool2 (行为调查)
         ↓                    ↓
Tool6 (情感需求) → Tool9 (访谈) → Tool10 (问卷)
         ↓
Tool3 (四镜洞察) → Tool1 (产品灵魂) → Tool3b (创新) → Tool8 (生态)
                                                          ↓
                                                     Tool5 (文献)
```

每个工具的输出里应该**显式引用**前序工具的结论。

### 3. 双语策略
- **内部分析文档**：使用团队的工作语言（如中文）
- **面向用户的研究工具**（问卷、访谈）：使用**目标市场的语言**（如英文）
- 在SKILL.md中要求用户明确language requirement

### 4. 质量检查清单

对每个工具产出，检查：
- [ ] 是否引用了真实的用户原声/数据？
- [ ] 假设是否被标注为 `[HYPOTHESIS]`？
- [ ] 是否与已有知识库的结论矛盾？如果矛盾，是否解释了原因？
- [ ] 优先级排序是否有清晰的判断标准？
- [ ] 产出是否可直接用于下一步行动（而非还需要大量补充）？

## 常见陷阱

### 陷阱1：过度依赖模板填空
模板是骨架，但血肉来自真实数据。如果所有工具产出读起来像"某种MBA作业"，说明没有与具体产品的数据产生化学反应。

### 陷阱2：情感需求与功能需求混淆
- "我希望日历能同步" → 这是**功能需求**（Tool7）
- "我不想再一个人记住一切" → 这是**情感需求**（Tool6）
- 检验方法：如果句子里有具体的"系统动作"，大概率是功能需求

### 陷阱3：四镜洞察变成数据复述
四镜洞察的价值在于**跨数据源的综合解读**，不是对单一数据源的复述。
- ❌ "用户说同步很重要"（这是复述）
- ✅ "用户说Google Calendar够用，但同时维护了白板+便签+口头提醒三套系统——这种补偿行为暴露了一个没被说出口的需求"（这是洞察）

### 陷阱4：产品灵魂变成营销口号
产品灵魂不是给消费者看的广告文案，而是给团队看的**内部北极星**。它回答的是"这个产品为什么值得存在"，而不是"怎么让用户买它"。

## 执行效率

### 完整执行时间
- 单人执行（AI辅助）：约4-6小时
- 团队workshop形式：约2-3天（每个Phase半天）

### 关键加速点
1. **已有JTBD数据**大幅加速Phase 1和Phase 3
2. **竞品评论数据**大幅加速四镜洞察
3. **明确的市场定位**大幅加速产品灵魂和生态设计
