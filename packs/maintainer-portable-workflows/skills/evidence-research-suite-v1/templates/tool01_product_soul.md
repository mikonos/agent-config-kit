### 0.5.1 Release / 私下雇佣轴（Dichter v1 第 6 轴 · 强制）

> **强制**：Dichter motivational research 最核心的判定测试——用户**公开**不会承认、**私下**会 hire 这个产品的事。
> Tool 1 最容易出 BLOCKED 的点：四维动机看似齐全，但没有 release 轴，无法判定灵魂句是否真的抓到 hidden need。

| 层 | 用户会怎么说 | 例子（本产品场景）|
|---|---|---|
| **公开理由**（面对老板 / 媒体 / 公开 SNS / 家长群）| 用户敢公开说出来 hire 这个产品的理由 | "It's a smarter calendar." / "我家有四个孩子，需要个 AI 帮忙记日程。" |
| **闺蜜能说**（面对最亲近的 1-2 人）| 用户对最信任的人会说但不公开 | "I just couldn't keep track of everything in my head anymore." / "我真的快撑不住了，需要个东西帮我记。" |
| **私下雇佣**（连闺蜜也不一定说，深层动机）| 用户连闺蜜都不太会说、但产品真正解决的事 | "I want permission to not be the only one holding this. I want this house to keep its own memory." / "我想有个东西帮我把'不能下班'这件事卸下一点点。" |

**判定测试**：灵魂句（§1.1）的核心动力必须落在「私下雇佣」层；若读起来像「公开理由」或「闺蜜能说」——回头重写。

## 11. 品类跃迁阶段（通用 framework）

> 不是所有产品都跨四阶段。识别产品覆盖哪些阶段、从哪个阶段跳到哪个阶段是品类跃迁的关键判断。
> 通用 framework：**See → Think → Prepare → Coordinate**（认知/感知 → 智能/规划 → 执行/准备 → 协调/分发）。
> 若产品在 B2B / DevTool / SaaS 等场景，可替换为：**Observe → Diagnose → Recommend → Automate**。

| 阶段 | 含义 | 代表产品（含竞品）| 核心能力 | 本产品是否覆盖 |
|---|---|---|---|---|
| **See / Observe** | {展示信息，让用户看到} | {竞品} | {同步 + 展示} | {✓ / ✗} |
| **Think / Diagnose** | {替用户想到遗漏 / 诊断问题} | {— 或竞品} | {Prep Engine / Diagnostic Engine — 有状态} | {✓ / ✗} |
| **Prepare / Recommend** | {替用户准备 / 推荐方案} | {— 或竞品} | {Chaos Pilot / Recommendation Engine + Memory Layer} | {✓ / ✗} |
| **Coordinate / Automate** | {全生态各自看到自己要做的事 / 自动分发} | {— 或竞品} | {Member-Aware Dashboard / Multi-Stakeholder Sync} | {✓ / ✗} |

**品类跃迁判断**：{竞品} 停在 {阶段 X}。市面上没有产品到达 {阶段 Y}。**本产品从 {阶段 X} 直接跳到 {阶段 Z}** —— 因为 {结构性不对称优势 — 有状态架构 / 角色模型 / 分布式感知网络等}。

> 品类跃迁的结构性护城河 + 10 年后哪些特性会过时 / 哪些依然有价值 → 在「推断与证据」节展开。
