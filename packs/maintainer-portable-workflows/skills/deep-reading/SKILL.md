# deep-reading（深度阅读）

> 目标：把一份材料从“读过”变成“可检索、可复用、可对话”的知识网络节点。

## 适用输入

- URL（文章、报告、论文、产品文档）
- 附件（PDF/图片/视频转写）
- 用户粘贴的长文本
- 明确指代的材料（“这篇/这本/这个视频”）

## 输出物（最小闭环）

1. **结构笔记**（1 份）
   - 交代材料主张、证据、推理链、可证伪点、与你现有网络的关系
2. **原子笔记**（≥3 份，按需要）
   - 每张只讲一个可独立复用的观点/方法/定义/反例
3. **链接与入口**
   - **纵向 + 横向（拆分）**：每张原子笔记至少 **1 条纵向**（指回本轮结构笔记或材料锚点）+ **至少 1 条横向**（指向**非本任务目录**的既有 Vault 笔记）；正文见下「交叉链接节」
   - 更新 `03_索引/00_索引_关键词总表.md` 的入口（若新增关键词），并解释“回答什么问题”
4. **验收落盘**
   - 在 `task.md` 记录 SOP 裁决；“不建”是合法完成结果，只有“更新 / 新建”才修改 SOP 与统一索引
   - 更新 `memory/daily/<machine-id>/YYYY-MM-DD.md`（Intent/Changes；路径可用 `node .cursor/scripts/print-daily-memory-path.js` 解析，与 `vault-writing-preamble` 归位快查一致）
   - 未闭环事项输出 `dry run product-gtd-capture` 建议；老板确认后调用正式 product capture / update 写入当前家庭，不写 `memory/gtd/`

## 执行流程

### Phase A：建模（先把材料“拆成可验证的骨架”）

- **主张**：作者要让你相信什么？
- **证据**：用的是什么数据/案例/实验设置？哪些是声称、哪些可核验？
- **机制**：主张背后的因果链是什么？关键假设在哪里？
- **边界**：适用条件、失败条件、反例或替代解释是什么？
- **与既有网络对话**：这份材料在回答你系统里的哪个问题？

### Phase B：结构笔记（把骨架写成可回放的阅读路径）

- 建议结构：
  - 摘要（100–200 字）
  - 论证链（分段，标注“声称/证据/推理/不确定”）
  - 关键术语表（简短）
  - 反驳/反例（至少 1 条）
  - 可行动启发（与当前项目/索引的连接）

### Phase C：原子化（把可复用单元拆出来）

- 每张原子笔记：
  - 有 YAML frontmatter（按工作区规范，键名英文）
  - 只表达一个观点，并能独立阅读
  - **链接拓扑**：至少 **1 条纵向**（结构笔记/材料）+ **至少 1 条横向**（既有 Vault）；且须有 `## 与既有网络的交叉链接`（详见下文 Iron Rules · 链接拓扑）

### Phase D：入网（链接 + 关键词入口）

- 先读 `03_索引/00_索引_关键词总表.md`，避免新增重复/冲突关键词
- 新增关键词条目时必须写“当我想找什么问题时会来找它”

### Phase E：验收（必须展示）

按 `core-entry.mdc` 的验收清单逐项过一遍（四原则、归位、链接、分享价值、日记录、GTD dry-run 承诺建议、记忆同步）。


> **通用协议**：执行前读取 `.cursor/skills/vault-writing-preamble/SKILL.md`（Iron Law、YAML 规范、indexed 标记、归位快查）。

# 深度阅读 (Deep Reading)

> **核心理念**：不仅要理解世界（Understand），还要改变世界（Act）。
> **适用范围**：Book, Long-form Article, Research Report, Academic Paper.

## 专家座席 (The Council)

### 第零席：领域专家 (The Domain Authority)（强制，不可省略）

> **铁律**：方法论专家（Adler/Feynman/Luhmann）解决「怎么读」，但「读什么领域」必须由该领域最强大脑来定调。

**执行步骤（Phase 0 之前）**：
1. **识别材料的核心领域**：这篇文章/书/研报主要讲什么领域？（零售渠道？AI 架构？组织管理？品牌心理学？）
2. **选定领域专家**：从 core-entry 映射表或更精准的细分人物中选择（如零售→Sam Walton/波特、食品安全→非方法论专家可选行业权威）
3. **声明时领域专家在前**：「以 [领域专家] + Adler/Feynman/Luhmann 的视角来…」——领域专家定视角，方法论专家定流程

**领域专家的具体作用**：
- Phase 1（结构）：用领域专家的框架审视作者的论证是否成立（如波特审视渠道文章的竞争分析是否完整）
- Phase 3（原子笔记）：原子笔记的 `description` 用领域专家的语言提炼洞察（不是泛泛的费曼式白话，而是该领域的精准判断）
- Phase 5（终审）：Feynman 做去魅，但领域专家做**专业校准**——术语翻译得对不对、概念有没有过度简化

**禁止**：材料有明确领域时只选 Adler+Feynman+Luhmann 三人组而不选领域专家。这是本 skill 最常见的敷衍模式。

### 方法论座席（The Method Council）

1.  **Mortimer Adler** (The Architect): 负责结构化，提取核心命题和逻辑树。
2.  **The Pragmatist** (The Engineer): 负责工具化，提取可执行的 SOP、模板和清单。
3.  **Richard Feynman** (The Teacher): 负责解释力，确保概念去魅，用人话讲清楚。
4.  **Niklas Luhmann** (The Librarian): 负责连接性，确保知识入网，有机生长。
5.  **The Critics** (The Stress Testers): Musk, Socrates, Munger 负责压力测试和辩论；所有正式审查环节必须由独立 subagent 执行，主 agent 只负责吸收审查结论并补执行。

## 核心法则 (The Iron Rules)

1.  **Always Deep**: 无论输入长短，默认按最高规格处理（结构+工具+辩论）。
2.  **Case Fidelity (案例保真)**:
    *   **有原文/书在手**：禁止概括性改写；原子笔记中涉及案例、研究处须保留**具体数字、作者/机构、时间线、原话**（可标页码）。
    *   **无原文、仅摘要或记忆**：在笔记中标注 `来源: 本书/摘要，未核对原文`；保留能确定的专有名词与结论，**禁止编造细节**；Feynman 验收时标「案例保真：部分（无原文）」。
    *   **材料提供方法论案例时**：若 Method Note / SOP / checklist 使用了材料中的案例、用户原话或示例，必须配套一份 `证据摘录` 或在方法卡内列「原文锚点」表。没有原文锚点的方法卡只能写成二手框架，不能写成已被原文证明的操作标准。
3.  **No Vague Verbs (模糊词禁令)**: 禁止使用 "优化"、"加强"、"适当" 等虚词。必须转化为**具体动作**或**量化指标**。
4.  **Metadata Mandatory (元数据强制)**: 所有笔记必须包含 YAML Frontmatter，**禁止省略**以下字段（与仓库 `AGENTS.md` / `core-entry`「笔记元数据规范」一致；**键名一律英文**，便于 Obsidian 标签系统识别 `tags` 等）：
    ```yaml
    type: ...
    tags: [english-tag-one, english-tag-two]   # 或 YAML 多行列表；取值一律英文
    links: [...]
    description: ...          # 费曼式洞察，100字内
    date: YYYYMMDD
    source_skill: deep-reading
    epistemic_status: borrowed    # 书/文默认 borrowed；自推分析可改为 working / speculative
    confidence: 0.8              # 0.0-1.0；必填。见本条下 4.1
    ```
    *   **`tags`（取值）**：YAML 键名必须是 **`tags`**；数组内**每条标签为英文**（建议小写 `kebab-case`，或 Obsidian 嵌套 `parent/child`）。**禁止**用中文、空格或未规范化的中文短语作标签字面量；中文主题名写在正文与 `[[链接]]`，不塞进 `tags`。
    `description` 回答：这张笔记最值得告诉别人的一个洞察是什么？费曼会怎么介绍；供 index-note 归网时快速定性。
4.1 **Confidence Mandatory (置信度必填)**：每张原子/方法笔记的 `confidence` 字段**禁止省略**、**禁止打 0.5**。值域规则：
    *   `0.9-1.0`：原文明确写的（作者直接陈述、代码中显式实现、数据可直接验证）
    *   `0.6-0.8`：合理推断 + 有间接证据（共享数据结构、逻辑推导、多源交叉印证）
    *   `0.3-0.5`：推测/不确定（单源推断、类比迁移、缺乏直接证据）
    *   **禁止 0.5**：0.5 是「懒得想」的退化值，要么往上标到 0.6，要么往下标到 0.4。
5.  **No Chat-Only Delivery (禁止仅对话交付)** — **硬门禁，无默认例外**：
    *   **默认**：一旦按本 skill 执行（用户意图含「深度阅读 / 系统梳理 / 仔细研究 / 读书 / 读这篇 / 分析这篇」等材料消化，且你已进入本 workflow），**必须**从 Phase 0 起落盘：`05_每日记录/YYYY/MM/YYYYMMDD/<任务标识>_deep-reading/`（或同等任务文件夹）内至少含 **`task.md`** + **`YYYYMMDD_01_…_执行计划.md`**，并走完整 Phase 1–**6.5**，直至 DoD 与 workflow-audit 闭环。**禁止**仅用对话长文代替 vault 产出。
    *   **禁止虚构门闸**：不得使用「确认后落盘」「等用户再说一句再建文件夹」「README 级对话交付即可」等理由跳过落盘；本 skill **未授权**任何「先聊后问再落盘」的默认策略。
    *   **唯一例外**：用户**原文明确**声明只要口头结论、**不要**在工作区新建/修改笔记（例如「只做口头总结」「别落盘」）。此时须在回复**首部**用引用块或摘录**一字不差**贴出用户例外句，并仍可按 `memory/` 日志规则记录 Intent（不创建 `05_` 笔记）。
    *   **执行顺序提示**：通过 Agent 工具落盘时，**尽早**创建当日任务目录与 `task.md` / Phase 0 执行计划，避免先写完对话再返工补文件。
6.  **Link Topology (链接拓扑：纵向 vs 横向)** — **硬门禁**（与「Insight / 意外连接」验收一致）：
    *   **纵向 (vertical)**：至少 **1 条**指回本轮 **结构笔记** 或 **材料标题/来源**（可在「卢曼视角」或 `links` 首项体现）。
    *   **横向 (lateral)**：至少 **1 条**指向 **既有 Vault**——即目标笔记路径**不在**当前任务目录 `…/<任务标识>_deep-reading/` 内（通常为 `03_索引/`、他日 `05_每日记录/` 等既有卡片）。
    *   **交叉链接节（正文强制）**：每张原子笔记须有 `## 与既有网络的交叉链接`，其中至少 **2 条** `[[wikilink]]` 为**横向**（同上：路径不在本任务目录内）。**本任务目录内**其他原子仅作阅读顺序/论证邻接，**不计入**这 2 条横向配额。
    *   **检索义务**：撰写交叉链接节前须读取 **`03_索引/00_索引_关键词总表.md`** 与 **`.cursor/skills/link-proposer/SKILL.md`**，按 link-proposer **Step 1–2.5** 产生候选；**至少采纳 1 条**候选写入正文或 `links`（与已有链接去重）。若采纳后仍不足 2 条横向，继续用 `rg` 检索核心短语、同义词、关键人名/项目名，直至满足或触发下款例外。
    *   **例外（真源可证）**：若经关键词总表 + link-proposer + `rg` 后，**可验证的**既有笔记仍不足 2 条可链，在该节写明：「检索：已执行关键词总表 + link-proposer + rg；可横向链 N 条；不足 2 条之差额记为待补链（见 `task.md`）。」**禁止**无检索说明地留空。
7.  **Roundtable Synthesis Must Be a Node (专家圆桌综合必须成卡)**：
    *   如果专家圆桌（Phase 3 的 Luhmann Scan 或结构笔记中的 Critics 座席）产出了**新的推理链**（A→B→C）或**新的综合判断**，必须创建一张 `type: Synthesis_Note` 卡片。
    *   `epistemic_status: working`（不是 borrowed——这是你自己的综合判断）。
    *   这张卡的双链指向结构笔记 + 被引用的原子卡片。
    *   **例外**：如果圆桌结论仅为「同意/不同意作者」而无新推理链，不需要独立成卡。

## 工作流程 (The Workflow)

**执行顺序**：Phase 0 → 1 → 2 → 2.5 → **2.75** → 3 → 4 → 5 → 6 → **6.5（流程执行审查，强制）**，不可跳步；Phase 2.5 须在 Phase 2 完成后立即执行；**Phase 2.75 须在 Phase 3 开始前完成**；Phase 6.5 须在 Phase 6 完成后立即执行。

### Phase 0: Pre-game Plan (准备)

在开始 Phase 1 前产出执行计划；落盘为 `YYYYMMDD_01_[书名]_执行计划.md`（与结构笔记同目录），并在 task.md 的 Preparation 下链接该文件。

确保包含：
1.  **TODO List** (≥6 项)：如全书论证骨架、关键概念、论证链、框架提取、方法提取、案例核实、批判性审查、入网连接。
2.  **Context**：读取意图（我要解决什么问题？）。

### Phase 1: Overview & Structure (概览与骨架)

**Agent**: Mortimer Adler

1.  **任务**: 创建结构笔记；产出须符合 `templates/structure_note_template.md`，含核心命题、逻辑支撑链与**阅读顺序 (Reading Sequence)**（每序列列出笔记顺序；该顺序将作为 Phase 3「阅读顺序链」的权威来源）。逻辑树与阅读顺序中的 `[[链接]]` 须为**真实暂定标题**（非模板占位），否则 Phase 2.75 无法通过。
2.  **说明**: 强制调用 `structure-note` skill

### Phase 2: Index Design (索引设计)

**Agent**: Niklas Luhmann

> "不要问它属于哪个分类，问它和谁对话。"

1.  **任务**: 为本书/本文创建索引笔记；产出须符合 `templates/index_note_template.md`，含关键词与多入口。
2.  **索引命名（强制）**：索引**文件名与标题**必须按**领域**命名，与 **file-organize** `references/03索引实现MOC流程.md` 的「索引层级与命名约定」一致：
    *   **必须**：从材料内容提炼**知识领域**（如「AI产品观与能力观」「多Agent与一人公司」），用领域名作为 `索引_<主题>_<领域>.md` 中的 `<领域>`。
    *   **禁止**：用材料名（书名/文章名/作者/来源/活动名/日期）作为索引名；这些信息只写在索引正文的「**来源说明**」或 frontmatter，不得进入文件名。
    *   **执行顺序**：先定领域名 → 再创建索引笔记 → 正文内写来源说明（例：「本索引内容主要来自 [书名/访谈名]，深度阅读产出见 [路径]」）。
3.  **说明**: 强制调用 `index-note` skill；调用前先完成「领域名」决策。

### Phase 2.5: 索引笔记入网（挂载）+ 归位

**Agent**: Niklas Luhmann

索引笔记创建完成后立即执行：**入网**（在已存在索引中挂载）→ **归位**（物理移动到 03_索引）。

1.  **入网（挂载）**：在 `03_索引/` 下选定一个（或多个）与本书主题相关的**已存在索引**，在其中添加入口指向本索引笔记（如子专题表追加 `- [[本索引笔记名]] — 领域简述，YYYYMMDD`；**说明用领域简述，不用书名/来源**）。本索引笔记底部链回该父索引。
2.  **归位**：将本索引笔记**文件**从当前任务目录（`05_每日记录/.../`）**移动**到 `03_索引/` 下合适位置（根目录或某主题子文件夹）。移动后父索引中的 `[[本索引笔记名]]` 仍有效（仅文件名，不依赖路径）。
3.  **多索引挂载检查**延后至 Phase 6：本索引内提到的笔记还可挂到哪些其他索引，届时统一检查并添加入口。

### Phase 2.75: Phase 3 前置门禁（显式链接全集）

**Agent**: Mortimer Adler + Niklas Luhmann

> **脆弱步骤低自由度**：未通过本节不得开始 Phase 3 的 **Sweep 2+（血肉/边缘）**；仅允许在通过后执行「扩展型」建卡。详见 skill-creator 工作流模式。

**显式链接全集（Round-1 清单）** 的权威定义：

### Phase 3: Recursive Growth (递归生长)

**Agent**: Luhmann & Feynman

> 核心创新：边创建边发现 (Luhmann Scan)。

**术语（避免混淆）**：

| 用语 | 含义 |
|------|------|
| **显式链接全集** | Phase 2.75 锁定；即本轮必须先落地的概念卡清单（骨架）。 |
| **Phase 3 Sweep 1 / 2 / 3+** | **工作波次**：骨架 → 血肉 → 边缘；见下列流程。 |
| **Scan-R2 / Scan-R3（记录标签）** | 仅用于 `task.md` 中 **Luhmann Scan** 行内格式，指「由 Scan 发现的后续待建链接批次」，**与 Sweep 编号不同**；完整定义见 `references/luhmann_scan.md`「Scan 产出轮次」。 |

**保真 vs 扩展**：本书/材料**主论证链**上的原子笔记优先满足 **Case Fidelity（案例保真）**。Scan 产生的外围概念：若超出本书范围或仅需占位，允许 **stub**（短定义 + 链）或**仅记链接待以后扩展**；止损条件见 `luhmann_scan.md`「何时停止？」。

**流程**:
1.  **Sweep 1 (骨架)**: 为 **显式链接全集**中的每个链接创建 **Atomic Note (概念)**；每张创建后执行 **Luhmann Scan**（见 `references/luhmann_scan.md`）。
2.  **Luhmann Scan (每张必做)**：三项——前置依赖、潜在连接、**方法论发现**（若概念附带可执行 how → 作为候选记入 task，交由 Phase 4 裁决，不预先创建 Method Note）。在 task.md 中每张卡记录格式：`前置 → Scan-R2: [[A]]. 连接 → Scan-R3: [[B]]. 方法候选 → 方法名或“无” (Phase 4 裁决).`（`Scan-R2/R3` 为 **Scan 记录标签**，勿与 Sweep 编号混用。）
3.  **Sweep 2 (血肉)**（仅 Phase 2.75 通过后）: 创建 Scan 发现的、理解本书仍需要的笔记，继续 Luhmann Scan。
4.  **Sweep 3+ (边缘)**（仅 Phase 2.75 通过后）: 直到完成或超出范围（见 `luhmann_scan.md` 止损条款）。

**Atomic Note 规范**:
*   **模板**: `templates/atomic_note_template.md`
*   **聚焦**: 定义 (Definition)、机制 (Mechanism)、语境 (Context)。
*   **验收**: 费曼测试 (外行能听懂)。

**横向交叉链接 + link-proposer（Phase 3 强制子步骤）**:
*   **时机**：每张原子笔记**正文初稿完成后**、Sweep 转入下一张之前，必须完成本节。
*   **步骤**：① `memsearch`（至少 1 个与概念相关的查询串）→ ② 按 **link-proposer** `SKILL.md` 执行 Step 1–2.5（含路径 C 张力抽样若环境允许）→ ③ 填写 `## 与既有网络的交叉链接`：**≥2 条横向** `[[wikilink]]`（路径不在本任务目录）**或** Iron Rules 6 的「例外」全文；**至少采纳 1 条** link-proposer 候选（若与 memsearch 重复则合并说明）。
*   **task.md**：在对应原子条目下追加一行：`横向：2/2 或 例外已说明；link-proposer：已执行`。

**阅读顺序链 (Reading-Order Chain)**（强制）:
*   **卢曼策略**：阅读路径应长在**网络里**，而非只存在于结构笔记这一张「地图」。Folgezettel 思维——序列本身是一条链，每张卡带「上一张 / 下一张」，读者无需回到结构笔记即可顺次阅读。
*   **技能契约**：凡被列入结构笔记「阅读顺序」的笔记，**必须在笔记内**建立序列内前后链接（见 atomic 模板「阅读顺序导航」）。结构笔记是入口；一旦进入某 Sequence，由各笔记的「上一张 / 下一张」承担延续阅读。
*   **执行**：**Sweep 1** 创建完某 Sequence 中的笔记后，逐张检查并补全「阅读顺序导航」：首张无上一张、末张无下一张可标「—」或省略；中间张必须含 `← [[上一张]] | [[下一张]] →`。

### Phase 4: SOP Disposition (SOP 裁决)

**Agent**: The Pragmatist

目标不是让每篇材料都生成 SOP，而是判断它是否为系统带来可复用的执行增量。**本阶段不自动创建或修改 Skill。**

1. **查重**：
   - 先读 `03_索引/索引_可执行方法与SOP.md`，再用任务、目标结果和核心动作检索候选。
   - 阅读最相近的 1–3 份 canonical SOP 全文；没有候选时在 `task.md` 明确写“未发现”。
2. **记录裁决**：在 `task.md` 增加以下区块，不得省略：
   ```markdown
   # SOP 裁决（Phase 4）
   - 最相近已有 SOP：
   - 本文带来的可执行差异：
   - 裁决：不建｜更新｜新建｜待审
   - 目标文件：
   - 理由：
   ```
3. **裁决标准**：
   - **不建**：材料只有观点、案例或弱证据，不能形成独立可执行增量；保留证据与原子笔记即可。
   - **更新**：候选 SOP 的触发任务和主要输出相同，本文只增加步骤、边界、证据、门禁或例外；优先手术式更新已有 canonical SOP，不另建重复文件。
   - **新建**：它解决的是不同的重复性任务，没有等价 SOP，并且能写清触发条件、输入、步骤、输出与验收。
   - **待审**：材料不足，或无法可靠区分“更新 / 新建”；记录缺口并停止本轮 SOP 写入，不修改 SOP 与索引；deep-reading 的其余 Phase 照常完成。
4. **执行与收尾**：
   - 只有裁决为“更新 / 新建”时，才修改或创建 Method Note；只改本次增量，不顺手重写旧 SOP。
   - 同一轮更新 `03_索引/索引_可执行方法与SOP.md`，使入口写清何时用、输入、输出、门禁和状态，并验证索引链接可以解析到 canonical SOP。
   - 若发现未来可能值得 Skill 化，只在 `task.md` 记录一行 `Skill 后续建议：<对象与理由>`；本阶段不创建或更新 Skill。

**Method Note 规范**（仅适用于“更新 / 新建”，高优先级）:
1.  **模板**: `templates/method_note_template.md`
2.  **聚焦**: 可执行步骤 (SOP)、模板 (Template)、检查清单 (Checklist)。
3.  **约束**:
    *   **No Vague Verbs**: 无模糊动词。
    *   **Mechanism & Leverage**: 为什么有效？
    *   **MVE**: 下一步最小可行性实验，必须精确到"今天能做的第一个动作"。
4.  **实战化要求（"操作手册版"而不是学术交流）**:
    *   **步骤用表格**：若工具有多步骤，每步用 `| 步骤 | What（做什么） | How（怎么做） | Why（为什么） |` 表格；禁止只用纯段落描述步骤。
    *   **每步必须有原文案例**：每个步骤下必须有来自原文的真实案例锚定（人名/数据/场景），不能悬空。无案例的步骤是抽象的，不是方法论。
    *   **每步必须有完成标准**：明确说明"做到什么程度算完成这步"，不能留给读者自行判断。
    *   **卡点随步走**：每步之后嵌入「最常见的错 → 即时对策」，不要把所有避坑集中到最后。
    *   **使用者自评清单**：除了产出验收清单（结果是否达标），再加一份「我自己做得对不对」的执行行为自检。
    *   **准备阶段独立**：需有独立的「准备阶段清单 (Pre-flight)」——开始前需确认的事项。
5.  **费曼测试（完成后必做）**：把写好的 Method Note 交给一个"刚意识到自己有这个问题的人"，问他：**"明天你会做什么？"** 如果他答不上来具体动作，说明 Method Note 仍然太抽象，必须返工。

由独立 readonly subagent 用 Feynman 标准审视整个知识网络；主 agent 不得用自评替代。subagent 输出问题清单、风险等级与补改建议，主 agent 负责逐条补执行并在 `task.md` 记录处理结果。

## 执行反模式（自检用）

> 以下是最常见的执行失败模式。每完成一个 Phase 后对照检查。

### 反模式 1：按论文章节做摘要，而非按洞察拆解
- **症状**：原子笔记标题含「与XXX」（如「Skill三组件与生命周期管线」），一张卡覆盖多个独立概念
- **检验**：每张原子笔记的 `description` 是否只讲一个可独立复用的观点？如果描述中出现「和」「与」以及连接两个以上概念 → 大概率是 compound atom
- **修正**：拆成 N 张独立卡片，每张只表达一个洞察，通过 ← → 链接串联

### 反模式 2：强制每篇阅读产出 Method Note
- **症状**：不看材料质量与主题重叠，Phase 4 总是新建一张 Method Note
- **检验**：是否先读统一 SOP 索引和最相近候选？`task.md` 是否能说明为什么是“不建 / 更新 / 新建 / 待审”？
- **修正**：先做 SOP 裁决；证据不足时“不建”，任务相同时“更新”，无法判断时“待审”，只有独立重复任务才“新建”

### 反模式 3：领域专家形同虚设
- **症状**：Phase 0 选了领域专家但 Phase 1-3 的产出里没有出现该专家的视角
- **检验**：结构笔记和原子笔记中是否至少 3 处出现了领域专家的校准/对比/批判？
- **修正**：每张核心原子笔记加一段「领域专家校准」——用该专家的框架审视这个洞察

### 反模式 4：只有正面摘要，没有批判
- **症状**：所有笔记都在复述作者说了什么，没有「论文没说但应该说的」
- **检验**：是否有至少 1 张批判性原子笔记？
- **修正**：强制增加「论文盲点」原子笔记，含具体缺失 + 我的增量
