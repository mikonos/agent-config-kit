# Agent 执行计划：JTBD 桌面研究 · [产品名]

> **执行者**：AI Agent（可并行执行多任务）
> **目标**：从公开渠道系统挖掘用户原声，填充「[产品/场景]」的 JTBD 图谱
> **不做**：不设计问卷、不进行真实访谈、不联系用户；只挖掘已公开的文字记录
> **输出**：按格式提取的原始引用库 + JTBD 综合分析报告

---

## 0. 执行节奏与时间箱

- **总时间预算**：建议净投入约 **2 天采集 + 1 天分析与写作**，可拆散执行，但尽量在一周内完成闭环。
- **批次优先级**：
  - **必做（Must）**：Batch 1（Reddit）、Batch 2（Amazon）、Batch 3（论坛/社区）
  - **在必做完成且有余力时执行（Should）**：Batch 4（App Store / Google Play）、Batch 5（YouTube）
  - **可选（Nice to have）**：Batch 6（Product Hunt / Twitter / Kickstarter）
- **最低完成线**：在时间不足时，优先保证：
  - 每个必做 Batch 至少完成 **50–70% 数量目标**；
  - 每个必做 Batch 覆盖到 **至少 3 种不同来源/子版块/ASIN**，避免只集中在单一线程。

## 二、JTBD 提取框架（所有任务统一使用）

### 每条引用的提取格式

```
[QUOTE-###] 或 [R-XX-###]
来源：（平台 + 版块/ASIN/频道名）
URL：（直链，如有）
原文：「……原文……」（尽量完整，不截断语意）
Job 标签：J1/J2/J3/J4（可多选）
四力标签：Push / Pull / Anxiety / Habit（选 1–2 个）
信号类型：痛苦陈述 / Workaround描述 / 雇用时刻 / 解雇时刻 / 需求表达 / 情感表达
强度信号：点赞数/评论数/引用次数（如可获取）
备注：（可选，注明特殊上下文）
```

### 四力信号识别指引

| 标签 | 识别关键词/句式 |
|------|----------------|
| **Push** | "I'm so frustrated with…", "every morning we…", "I always forget…", "it drives me crazy", "我受够了", "每次都忘" |
| **Pull** | "I want…", "wish there was…", "love this feature", "transformed my…", "become reliant on", "我想要", "希望有" |
| **Anxiety** | "too expensive", "too complex", "worried about…", "what if it breaks", "my wife won't let me", "太贵了", "担心" |
| **Habit** | "we currently use…", "I've always done…", "good enough for now", "just use a whiteboard", "一直在用", "习惯了" |

### 信号类型定义

- **痛苦陈述**：用户描述当前痛点、不满、焦虑
- **Workaround 描述**：用户描述现有解决方案及其不足
- **雇用时刻**：用户描述什么触发了寻找新解法
- **解雇时刻**：用户描述为什么放弃某个解法
- **需求表达**：用户明确表达想要什么
- **情感表达**：强烈的情感词汇（love, hate, frustrated, saved my life）

## 五、质量控制原则

1. **忠实记录，不推断**：原文引用要完整，不得改写或总结替代。分析和推断放在备注或报告中，不混入原文。
2. **找不到写「未找到」**：若某平台确实没有相关内容，在对应 Task 下注明，不猜测或填充。
3. **优先级排序**：Batch 1 → Batch 2 → Batch 3 → Batch 4 → Batch 5 → Batch 6；若时间有限，优先保证 Batch 1–3 完整。
4. **去重与多平台信号**：同一表达在多平台出现时，只保留信息最完整的一条，其他平台在 `备注` 中通过 `multi-platform: ...` 标注。
5. **信号强度优先**：高赞评论 > 低赞评论；长帖详述 > 短评；具体场景描述 > 泛泛抱怨。
6. **不联系用户**：纯桌面研究，不发私信、不回帖、不评论。
7. **截图存档（如可）**：对特别高质量的原帖，记录帖子 URL 以便人工复核。
8. **注意反证样本**：在采样时有意识保留「不认同问题严重性」「对现有方案满意」「质疑产品形态」的声音，避免样本只由「支持我们假设的人」构成。反证样本目标占比：15-30%。
