# Automation Notes

## Pre-authorized Default

The user has requested that future scheduled runs can send the generated report without a per-run confirmation when the automation is fixed to:

- GitHub repository: `sunsetyyun/project`
- Feishu group name: `产品开发`
- Sender identity: `bot`
- Content source: `scripts/project_issue_launch_report.py`
- Report purpose: product-launch issue status and recent open/closed trend

This preauthorization is narrow. It does not cover arbitrary free-form messages, other groups, direct messages, destructive operations, issue mutations, or Feishu recalls/deletes.

## Safe Automation Prompt Shape

When creating a Codex automation, use the automation tool instead of writing raw automation files. The prompt should say:

```text
Use .cursor/skills/project-launch-report/SKILL.md.
Generate the project issue launch report from live GitHub data.
Search Feishu group by exact name "产品开发" using bot identity.
If exactly one normal group named "产品开发" is found, send the generated report as bot without asking for per-run confirmation.
If group search returns zero or multiple matches, or GitHub/lark auth fails, do not send; report the blocker.
Do not mutate GitHub issues. Do not send any content not generated by the report script.
```

## Suggested Schedule

For a workday daily report, use a weekday morning or afternoon cron. Keep the timezone explicit in the automation UI/prompt. If the automation system accepts RRULE, use the app's suggested-create flow so the user can review the schedule before saving.

## Runtime Safety Gate

Before sending, the automation must verify:

1. `gh issue list` succeeded for `sunsetyyun/project`.
2. The report is non-empty and includes `Open` and `Closed` totals.
3. Feishu group search returns exactly one chat.
4. The chat name exactly equals `产品开发`.
5. The chat status is `normal`.
6. The send command uses `--as bot`.

If any check fails, stop without sending.
